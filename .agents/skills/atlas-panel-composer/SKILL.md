# Atlas Panel Composer

Build panels as visual arguments, not mood boards. Make the arrangement legible enough to test, while preserving productive intervals and unresolved tensions.

## Workflow

1. Define the panel question in one sentence. If the user supplies only images, infer a provisional question and label it provisional.
2. Inventory the candidate objects and verify their metadata and provenance. Use Mnemosyne Research Atelier first when identifications are unstable.
3. Exclude items that are merely decorative, redundant, insufficiently documented, or unrelated to the question.
4. Identify the panel's organizing operations:
   - recurrence;
   - inversion;
   - displacement;
   - scale change;
   - gesture or posture;
   - attribute transfer;
   - institutional reuse;
   - temporal survival or rupture;
   - legal-political transformation.
5. Select four to twelve primary objects unless the requested format requires another count.
6. Define one dominant axis and no more than two secondary axes.
7. Arrange the panel using `references/layout-grammar.md`. Use adjacency, distance, scale, crop, and empty space as argumentative devices.
8. Produce a numbered wireframe and a reading path. When image tools are available and the user requests it, create a visual mockup after the conceptual plan is stable.
9. Test at least one alternative layout and explain what interpretation changes.
10. Run the methodological cautions in `references/warburgian-cautions.md` before finalizing.

## Default output

# Panel [number or provisional title]

## Panel proposition
State the claim, tension, or question in two to four sentences.

## Selection table
For each object include:
- object number;
- short identification;
- date and source;
- role in the panel;
- relation to adjacent objects;
- confidence and metadata gaps.

## Conceptual architecture
Explain the dominant axis, secondary axes, polarities, repetitions, reversals, and the unresolved remainder.

## Layout plan
Provide:
- canvas ratio and orientation;
- numbered grid or coordinate map;
- relative size of each object;
- crop instructions;
- spacing and negative-space instructions;
- reading paths;
- caption strategy.

Use the notation in `references/panel-output-template.md`.

## Alternative arrangement
Show one meaningful alternate configuration and explain the interpretive consequence.

## Evidentiary limits
Separate documented transmission from typological recurrence, formal resemblance, and exploratory association.

## Next research actions
List only actions that could materially strengthen or falsify the panel.

## Composition principles

- Organize by tension, transformation, and interval, not by chronology alone.
- Let visual scale indicate argumentative weight, not aesthetic preference.
- Use repetition sparingly; each repeated motif must perform a different function.
- Preserve at least one productive discontinuity. A panel that explains everything is usually dead.
- Never use a visually dramatic object only to make the panel attractive.
- Do not force symmetry when asymmetry better represents the archive or argument.
- Keep captions subordinate to the visual field, but make identifiers recoverable.
- Maintain a source list outside the visual field when the panel is for publication.

## Handoffs

- Send unstable identifications back to Mnemosyne Research Atelier.
- Send approved panel content to Iconocracy Web Editor for publication.
- Send the proposition and object sequence to Thesis Chapter Architect when the panel supports a chapter.
- Send the near-final panel to Intellectual Tastekeeper for a severe review.
