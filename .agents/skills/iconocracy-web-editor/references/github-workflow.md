# GitHub workflow

1. Confirm repository and default branch.
2. Inspect status, contributor instructions, framework, package manager, and existing content examples.
3. Create a focused branch unless direct default-branch editing is explicitly authorized.
4. Make the smallest coherent change set.
5. Run repository-native checks.
6. Review diff for secrets, private materials, generated files, broken paths, and accidental reformatting.
7. Commit with a descriptive message.
8. Open or update a pull request when supported.
9. Merge or deploy only with explicit authorization.

In the report include branch, commit or pull request reference when available, checks run, and unresolved risks.
