# ADR -- Lacunas documentadas no freeze piloto do codebook v2.3.0

## 1. Enquadramento

O patch v2.3.0 (commit `cc0bb31`) promoveu o codebook LPAI para o estado
`pre_freeze_piloto_v230` com **5 lacunas explicitamente documentadas** em
`schema/codebook-v2.3.0.md` (marcadores `nota_lacuna` em §9) e um
validator升级 (commit `49caba3`) que emite **warnings**, nao errors.

Este ADR formaliza a decisao de **promover v2.3.0 com lacunas registradas
em vez de tapalas com busca adicional** antes do freeze real.

## 2. As 5 lacunas (resumo)

| ID | Marcador | Onde | Sub-linhagem afetada |
|----|----------|------|---------------------|
| L1 | `Pele_Leao` | enum `objetos_regalia` | Hercules juridico (adendo §2) |
| L2 | `Tridente_Imperial` | enum `objetos_regalia` | Netuno / soberania maritima (adendo §5) |
| L3 | `Ancora_Naval` | enum `objetos_regalia` | Atlantes + Netuno (adendo §3, §5) |
| L4 | `classicizacao` | indicador `purificacao` | transversal |
| L5 | `depuracao_semantica` | indicador `purificacao` | transversal / Genio do Brasil (adendo §6) |

Detalhamento individual em `schema/codebook-v2.3.0.md` §14.

## 3. Decisao (D-2026-06-25-01)

**v2.3.0 sera promovida a master_record quando, e somente quando:**

1. L1, L2, L3 (valores enum novos) tiverem **pelo menos 1 fonte primaria
   direta** cada, registrada em `exports.abnt_citations` com formato ABNT
   NBR 6023:2025 completo.
2. L4, L5 (indicadores) tiverem **criterio operacional escrito** (1 pagina
   cada) descrevendo como pontuar 0/1/2/3 de forma reprodutivel.
3. Os 5 gates declarados em `commit cc0bb31` ("Bloqueios para freeze real")
   estiverem resolvidos ou formalmente transferidos para v2.4.0+ via ADR.

**Ate la**, o corpus pode ser codificado com os campos novos **vazios**
(opcionais), e os registros que usam L1/L2/L3/L4/L5 ficam **sinalizados**
para tratamento prioritario na proxima rodada Elicit (prevista para
julho-agosto 2026).

## 4. Justificativa epistemologica

A decisao segue o principio **capta** (Drucker 2011, internalizado no
codebook em v2.x via `capta_declaration`): dados sao **tomados e
construidos**, nao encontrados. Inventar conteudo para fechar lacunas
seria pior do que registra-las porque:

1. **Violaria o proprio principio que o codebook encarna.** O campo
   `capta_declaration` exige que o codificador declare suas escolhas
   interpretativas; tapar lacuna sem evidencia seria o oposto.

2. **O validator升级 emitiria warnings de `HERCULES_INCOERENTE`** em
   substituicoes sem lastro (commit 49caba3). Promover lacunas a
   "conteudo provisorios" sem ancora quebraria a propria auditoria que
   acabamos de instalar.

3. **A consulta Elicit deste piloto foi desenhada para validar a estrutura
   do patch** (5 campos novos, regra de genero, validacao), nao para
   esgotar a evidencia de cada valor enum. Esgotar evidencia e trabalho
   da v2.4.0+, e **distinguir estrutura de conteudo** e o que faz uma
   consulta Elicit de uma pesquisa de doutorado.

4. **A opacidade e pior do que a lacuna visivel.** Um leitor futuro do
   codebook que encontra "Pele_Leao" sem fonte nao sabe se o autor nao
   encontrou fonte ou se propositalmente omitiu. O registro `nota_lacuna`
   + secao §14 explicita a **honestidade epistemologica** do freeze.

## 5. Riscos do modelo (R-2026-06-25)

- **R1 -- Usos nao-sinalizados**: registros que usam L1/L2/L3 sem o
  codificador ter visto §14 podem poluir o corpus. Mitigacao:
  `validate_schemas.py` ja emite `REQUIRES_V23_FIELDS` quando
  `familia_alegorica == Masculino_Juridico` sem campos novos (warning);
  promover a error em v2.4.0+.
- **R2 -- Freeze eterno**: se L1/L2/L3 nunca forem cobertos, v2.3.0 fica
  em `pre_freeze_piloto_v230` para sempre. Mitigacao: ADR define gatilho
  temporal (proxima rodada Elicit = julho-agosto 2026); se nao acontecer,
  reavaliar em setembro 2026.
- **R3 -- Divergencia com master_record v2.2.0**: enquanto v2.3.0 nao
  for promoted, o corpus codifica com campos novos **opcionais** que a
  v2.2.0 nao conhece. Mitigacao: o `validate_schemas.py`升级 preserva
  compatibilidade (campos novos sao `additionalProperties: true` em
  `purificacao`); corpusdata export continua funcionando.
