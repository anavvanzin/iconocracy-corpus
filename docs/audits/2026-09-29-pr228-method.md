Main integrado: `39170627eb6a91a84928bb87c0086f0d9d8d48f2`, incluindo #227 e #229.
A integração não exigiu resolução de conflitos.

P1: v2 reutiliza `entry_year` do v1 em cadeias, relações binárias, flags e
relatórios. Datas textuais usam o primeiro ano como referência aproximada,
sem criar nova datação. Cadeias com qualquer data ausente retornam
`chain_dates_unavailable`; membros ausentes não são descartados para classificar
uma subcadeia. A cadeia demo 1781–1915 retorna `weak_chain`, não constelação temporal.

P2: as observações são carregadas separadamente de
`data/processed/purification.jsonl` e unidas por ID. V1 usa o ledger nas
transições; v2 também usa o ledger no relatório de cadeias. Metadados continuam
vindo do corpus, mas seus indicadores projetados não entram nas comparações.
Linhas/dimensões ausentes permanecem indisponíveis; zeros registrados são
preservados (incluindo BE-004). Ledger inexistente, inválido ou com IDs duplicados
não pode produzir silenciosamente um relatório bem-sucedido.

Ambos os comandos aceitam `--purification CAMINHO`; por padrão usam o ledger
canônico do repositório:

```bash
python tools/audit/scripts/analyze_threads.py corpus/corpus-data.json --demo
python tools/audit/scripts/analyze_threads_v2.py corpus/corpus-data.json --demo
python tools/audit/scripts/analyze_threads.py corpus/corpus-data.json painel.json --purification data/processed/purification.jsonl
```

Nenhuma média, soma, delta agregado ou cardinalidade substitui o composto
aposentado. As comparações mantêm observações nomeadas por dimensão. Cronologia
não prova descendência histórica; demos são sintéticos, não evidência empírica.
